# SP-z-privacy-offline — 오프라인 수명과 사용자 데이터 통제

상태: **채택**. 2026-10-07.

사용자 결정: JunTae Park (준태, 저장소 소유자), 2026-10-07 12:42 KST. 원문: "012·013·014·015·016 전부 채택한다. 게이트는 독립 리뷰 2회로 대체하고, user_merge도 네가 머지해라. 이후 z-노드도 같은 방식으로 끝까지 진행해."

이 기록은 z-privacy-offline만 다룬다. 같은 발화의 이후 z-노드는 각 노드에서 구현한다. Fable NONE과 비작성자 A2는 독립 읽기 전용 검토 2회로 대체한다. 머지 권한은 감독자에게 위임된다. 기록은 [Dz-privacy-offline](../../design/DECISIONS.md)이다. 이 채택은 런타임 배포, 계정, 결제, 클라우드, 사진 동의, 안전 인증, 출시, 실기기 검증이 아니다.

## 문제

네트워크가 없어도 채택 snapshot이 열리고 강제 종료 뒤에도 손상되지 않아야 한다. 저장소가 모자랄 때 저장되지 않은 것을 저장된 것처럼 보이면 안 된다. 사용자는 사진·검색 기록·프로젝트를 범위별로 내려받고 지울 수 있어야 하며, 어떤 동작이 연결을 필요로 하는지 알아야 한다. 구버전 앱 캐시가 새 저장 형식을 만나는 경우도 데이터를 바꾸지 않고 드러나야 한다.

## 결정

호스트(TypeScript)만 바꾼다. Rust·프로토콜·스키마·DB version·`BUILD_ID`·fixture는 바꾸지 않는다. 계산·수량·적합성 판정은 새로 하지 않는다.

- 화면은 `#/data`("내 데이터")다. 프로젝트별로 세 범위를 보인다: 프로젝트(JSON 보내기·삭제), 사진(장수·크기, 장별 내려받기, 사진 전체 삭제), 검색(위치 기록 관측 수, JSON 보내기, 삭제).
- 범위 삭제는 그 범위의 행만 한 트랜잭션에서 지운다(`deleteProjectPhotos`, `deleteLocationLog`, 기존 `deleteProject`). 완료는 행을 다시 읽어 사라졌음을 확인한 뒤에만 말한다. 실패하면 "지워진 것은 없습니다"이고 행은 그대로다. 내려받은 파일과 브라우저·운영체제 백업은 지울 수 없다고 적는다.
- 읽을 수 없는 행은 0이 아니라 "읽을 수 없는 기록"이다. 사용자는 그것도 지울 수 있다.
- 사진 내려받기는 위치·촬영 정보를 제거한 표시용 사본이며 원본이 아니다. 프로젝트 JSON은 기존 exportVersion 1이고 사진 바이트를 넣지 않는다. 위치 기록 JSON은 `zari-location-log` 설명 파일이고 이 앱은 가져오지 않는다. 사진 바이트를 이식 묶음에 넣는 일(사진 동의)은 하지 않는다.
- 저장 실패(`persistence_failed:quota` 포함)는 "저장되지 않았습니다"로 말하고 저장됨 상태를 만들지 않는다. 사진 첨부와 위치 패널의 오류 글이 이 문구를 쓴다. 저장 공간 사용량은 `navigator.storage.estimate()`이고 모르면 "알 수 없음"이며 0이 아니다. 80% 이상이면 경고한다.
- 호환 검사는 읽기 전용이다. 저장된 DB version(Dexie 4는 더 새로운 저장 version을 거절하지 않고 열 수 있으므로 backend version을 읽는다), 업그레이드 일지, 새 schema 행 수, 앱 캐시의 active/previous/staged build를 보인다. 더 새로운 저장소와 새 schema 행은 읽기만 하고 고치지 않는다.
- 연결 구분은 `features/privacy/connections.ts`의 한 목록이다: 완전 로컬 네 가지, 앱 파일 받기(같은 origin 정적 파일만), 직접 누른 판매처 링크. 외부 AI·분석 전송·계정 동기화는 "없음"이라고 쓴다. 정적 검사가 배포 소스에서 네트워크 API(fetch 등)가 서비스 워커에만 있고 그 워커가 same-origin GET과 자기 manifest만 다룸을 고정한다. 브라우저 시험은 요청이 모두 같은 origin의 본문 없는 GET임을 확인한다.

## 하지 않는 것

전체 기기 초기화(모든 프로젝트·카탈로그 삭제), `navigator.storage.persist()` 요청, 사진 바이트의 이식 묶음 포함, 위치 기록 JSON 가져오기, 구매·피드백·보유 이력의 개별 삭제 범위, 클라우드·계정, CSP 헤더 도입, 다음 z-노드. 승인된 화면 baseline을 바꾸지 않는다.
