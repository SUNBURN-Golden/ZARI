# SP-z-accessibility-workspace — 측정부터 실행까지 키보드·모바일 접근성

상태: **채택**. 2026-10-07.

사용자 결정: JunTae Park (준태, 저장소 소유자), 2026-10-07 12:42 KST. 원문: "012·013·014·015·016 전부 채택한다. 게이트는 독립 리뷰 2회로 대체하고, user_merge도 네가 머지해라. 이후 z-노드도 같은 방식으로 끝까지 진행해."

이 기록은 z-accessibility-workspace만 다룬다. 같은 발화의 이후 z-노드는 각 노드에서 구현한다. Fable NONE과 비작성자 A2는 독립 읽기 전용 검토 2회로 대체한다. 머지 권한은 감독자에게 위임된다. 기록은 [Dz-accessibility-workspace](../../design/DECISIONS.md)이다. 이 채택은 런타임 배포, 계정, 결제, 클라우드, 사진 동의, 안전 인증, 출시, 실기기 검증이 아니다.

## 문제

드래그를 못 쓰거나 화면이 좁으면 생성, 측정, 계산, 비교, 채택, 실행 가이드를 같은 권위로 끝내지 못한다. 선택·강조·오류·미확인이 색에만 있으면 보조기술이 놓친다. 저장 중 실패, 취소, 복구가 포커스나 입력 글자를 지우면 같은 작업을 다시 시작할 수 없다.

## 결정

계산은 기존 Rust `movePlacement`다. 좌표 입력, 도면 화살표, 터치 증감이 같은 명령을 보낸다. 호스트는 읽을 수 있는 정수 mm만 보내고, 빈 칸을 0mm로 바꾸지 않는다. 증감이 0이면 명령이 아니다.

- 키보드로 배치 버튼을 누르면 그 상세의 X 좌표 입력으로 포커스가 간다. 포인터 클릭은 포커스를 빼앗지 않는다. 좁은 화면에서는 선택 정보 시트를 연 뒤 같은 입력으로 간다.
- 터치 단위는 1mm 또는 10mm다. Shift를 누르는 동안 화살표와 표시 단위는 10mm이고, Shift를 떼면 터치가 고른 단위로 돌아간다. 화살표 자체는 기존 `keyboardStepMm`이다.
- 선택과 목록 강조는 보이는 표시와 `aria-live="polite"`에 함께 있다. 배치·도면·내용물·검사·구매 행·대안 비교의 선택 버튼은 `aria-pressed`다. 미확인 문장은 그 치수 입력의 `aria-describedby`에 연결된다. 저장 상태와 미확인 검사는 `role="status"`다.
- 저장 실패, 충돌, 워커 실패, 채택 오류가 나타나면 복구 컨트롤로 포커스가 가고, 사라지면 이전 포커스로 돌아간다. 필드 값은 지우지 않는다. 확정 시 포커스가 확정 버튼에 있고 측정 진단이 있으면 첫 오류 필드로 간다.
- 계산이 취소·중단·실패로 끝나면, 포커스가 없거나 취소 버튼에 있을 때만 계산 버튼으로 돌린다. 채택된 스냅샷이 바뀌면 실행 가이드 안의 사용할 수 있는 컨트롤로 포커스가 간다. 막힌 첫 버튼은 건너뛴다.
- 비교 표는 후보 카드와 채택 버튼보다 앞에 있어 키보드 순서가 계산, 진단, 비교, 채택, 가이드다.
- 47.999rem 아래에서 프로젝트 이름과 “이 기기에만 저장”은 숨기지 않고 다음 줄로 넘긴다. 비교 표는 `contain: inline-size`로 페이지 너비를 늘리지 않는다. coarse pointer에서 증감 버튼과 편집 입력은 기존 `--zari-touch-min-height`다.

`BUILD_ID`는 `zari-domain-7`이다. 프로토콜과 fixture 기대 바이트는 바꾸지 않는다. 새 색 토큰은 없다.

## 하지 않는 것

새 Rust 명령, 구매·클라우드·사진, 실전화·전용 GPU를 데스크톱 에뮬레이션으로 검증했다고 적기, 승인된 화면 baseline 교체, 다음 z-노드.
