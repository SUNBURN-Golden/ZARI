## 저장과 진행

의미 있는 사실·증빙 편집은 계획·조회·완료 자격을 무효로 둔다. 진단이 있는 원본 초안은 저장하고, 이미 있는 정규 입력과 다이제스트를 바꾸지 않는다.

카탈로그·판매 항목이 바뀌면 옛 가격·포장·증빙은 그 스냅샷에 남는다. 새 다이제스트와 명시적 재계산·채택이 있어야 다음 계획이다. 옛 BOM은 새 판매 항목을 빌리지 않는다. 화면의 판매 항목 목록은 그 계획의 `referencedCatalog`만 쓴다.

보유 라이브러리 수정은 프로젝트 사본에 자동으로 들어가지 않는다. 화면의 명시 버튼이 사본을 바꾼다. 가용 수량이 unknown이면 확정 단위를 쓰지 않는다. 사본과 다른 프로젝트는 같은 재고를 전역으로 예약하지 않는다.

상품이 없는 카탈로그는 `sourceKind` `imported`와 origin `empty-real`이다. 제품·옵션·판매 항목을 만들지 않는다. 직접 배치·보유·무구매가 그대로다.

## 실패와 복구

저장 한도·불가·CAS·롤백은 화면의 입력과 이전 done 행을 남긴다. 저장됨·완료·현재 재고·결제를 만들지 않는다. 보내기와 사본 경로를 보여 준다.

페이지·Worker·빌드 세대가 섞이면 실패로 닫는다. 옛 가이드와 옛 규칙은 읽기 전용이다. `zari-domain-v1` 완료는 거절하고 바이트를 고치지 않는다.

보내기·가져오기·복제는 Rust `verifyRecord`가 끝난 뒤에만 새 프로젝트 트랜잭션을 연다. 증빙과 역사 스냅샷은 남기고, 복제된 진행은 비우며, 사진은 빠졌다고 말한다. 트랜잭션 안에서 Worker를 기다리지 않는다.

트랩·하드 취소(취소 시간 초과, 정지, Worker 실패) 뒤에는 새 활성화가 있어야 계산을 다시 시작한다. 협조적 취소는 같은 활성화를 유지한다.

새 바인딩의 진행 자동 이월은 0이다. 역사 견적과 unknown 수량·가격·출처·신뢰를 다시 쓰지 않는다.
