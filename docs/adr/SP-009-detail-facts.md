# SP-009 — 오차·근거·v1 상세 사실 입력

상태: **채택**. 2026-10-07.

사용자 결정: JunTae Park (준태, 저장소 소유자), 2026-10-07 약 07:28 KST. 원문: "009·010·011 전부 채택한다. Fable 게이트는 각각 독립 리뷰 2회로 대체하고, 머지도 네가 해라."

이 기록은 SP-009만 다룬다. 같은 발화에서 SP-010과 SP-011도 채택되었으나 그 구현은 각 노드의 일이다. Fable MILESTONE과 비작성자 A2는 독립 읽기 전용 검토 2회로 대체한다. 머지 권한은 감독자에게 위임된다. 기록은 [D009](../../design/DECISIONS.md)이다.

## 문제

일반 프로젝트는 샘플의 지지·하중·여유를 사실처럼 물려받고, 오차·근거·staging·handling을 JSON 없이 넣지 못한다.

## 결정

SP-008이 구현하고 검증한 `normalizeInput` raw surface만 소비한다. `BUILD_ID`는 `zari-domain-5`로 유지한다. capability 목록, 생성 공개 계약, `queryNextFacts`는 바꾸지 않는다. query 활성화는 SP-010이다.

화면은 접힌 상태로 시작한다. `상세 측정`은 명시적 버튼이다. 명목값, 오차, 단위, 출처, 근거를 한 필드에서 다룬다. 접혀 있어도 `오차 미확인`을 보이고 0을 숨기지 않는다. 빈 경계는 0이 아니다. 한 경계가 빠지거나 잘못되면 정규화된 입력과 근거 전체의 커밋을 막되, 이전 커밋과 원문 초고의 저장·재로드는 유지한다.

Rust `groupFormatRequests`가 명목값과 경계를 함께 바꾸거나 거절한다. 거절된 그룹은 원래 문자열과 단위를 유지한다. 값이 없는 양의 길이만 단위 표시를 바꿀 수 있다. JavaScript는 숫자를 파싱하거나 반올림하지 않는다.

v1에서 다루는 경로는 입구 오프셋, staging cuboid와 지지·하중, 바닥 footprint·elevation·하중, 정적 여유, 동작 여유(handling), 검증된 item id의 수량·질량·치수다. 카탈로그와 보유 수납함 물리는 프로젝트에서 바꾸지 않고 기존 `#/catalog`로 보낸다.

새 `emptyProjectForm()`은 `space.staging.baseSupport`와 각 item handling 다섯 축을 정규화 전에 unknown으로 둔다. 샘플 채우기와 이미 저장된 프로젝트는 그대로다. 마이그레이션과 가져온 값 덮어쓰기는 없다.

`Evidence.note`만 사람이 쓴 관측 문장을 담는다. 충돌을 적은 문장은 출처의 주장이다. 엔진 충돌, 통과, 실패, 숫자 구간, 확인을 만들지 않는다. `UserMeasured`는 Unverified다. 관측 시각은 직접 입력할 때만 기록한다.

## 결과

정규화된 사실과 근거는 기존 CAS에 함께 저장된다. 수정은 즉시 stale이다. 초점과 그룹 이동은 revision과 DB를 바꾸지 않는다. 저장 실패 시 작업 중인 원문은 화면에 남는다.

여유·질량·수량은 raw에 단위 칸이 없다. 화면은 mm, g, 개로 두고 변환 결과를 다시 쓰지 않는다. 그 사실을 다른 단위로 저장하면 값이 바뀐다.
