# SP-z-guided-onboarding — 처음 사용해도 완성하는 예제와 빈 화면

상태: **채택**. 2026-10-07.

사용자 결정: JunTae Park (준태, 저장소 소유자), 2026-10-07 12:42 KST. 원문: "012·013·014·015·016 전부 채택한다. 게이트는 독립 리뷰 2회로 대체하고, user_merge도 네가 머지해라. 이후 z-노드도 같은 방식으로 끝까지 진행해."

이 기록은 z-guided-onboarding만 다룬다. 같은 발화의 이후 z-노드는 각 노드에서 구현한다. Fable NONE과 비작성자 A2는 독립 읽기 전용 검토 2회로 대체한다. 머지 권한은 감독자에게 위임된다. 기록은 [Dz-guided-onboarding](../../design/DECISIONS.md)이다. 이 채택은 런타임 배포, 계정, 결제, 클라우드, 사진 동의, 실제 상품·판매처 연결, 출시, 실기기 검증이 아니다.

## 문제

빈 작업대에서 시작한 사용자가 어떤 값을 먼저 재야 하는지, 어떤 모양으로 입력하는지, 오류를 어떻게 고치는지, 이 앱이 무엇까지 검사하는지 알 수 없다. 합성 샘플 값과 실제 새 프로젝트가 같은 버튼 근처에 섞여 있고, 합성 카탈로그의 "ACME Storage box · 12000"이 구매 가능한 상품처럼 보일 수 있다.

## 결정

호스트(TypeScript)만 바꾼다. Rust·프로토콜·스키마·DB version·`BUILD_ID`·fixture는 바꾸지 않는다. 계산·수량·적합성 판정은 새로 하지 않으며 안내는 입력 초안을 쓰지 않는다.

- 시작을 둘로 나눈다. "내 공간으로 시작"은 기존 빈 초안(`emptyProjectForm`)이고 "예제로 둘러보기"는 합성 샘플 값(`sampleProjectForm`)을 가진 별도 프로젝트다. 예제 프로젝트는 이름 접두 `예제 · 합성 데이터 (실제 상품 아님)`로 구분하고 저장 형식은 바꾸지 않는다. 목록에 "예제 · 합성" 표시와 화면 배너가 붙는다. 예제는 기존 프로젝트를 건드리지 않는다.
- 합성 카탈로그(고정 digest)를 쓰는 계획 화면과 구매 준비 패널은 프로젝트 이름과 무관하게 "합성 예제 자료이며 구매할 수 없다"는 문구를 보인다. 판매처 링크 글자는 "예제 링크 (실제 판매처 아님)"다. 링크 자체와 기존 구매 흐름은 바뀌지 않는다.
- 측정 화면에 안내 패널을 둔다: 단계(공간 안쪽 → 개구부(선택) → 물건(선택) → 확인·저장 → 계획 검토), 칸별 재는 법과 입력 예시, 오류 코드별 고치는 법, 지원 범위. "모든 칸을 먼저 채울 필요는 없다"고 쓰고 필수 단계는 공간 안쪽 세 값뿐이다.
- "지금 필요한 값"은 Rust 다음 사실(next-facts) 목록의 첫 측정 칸 행이다. 목록이 아직 없으면 안내 순서의 첫 빈 필수 칸이고, 그렇다고 글자로 밝힌다. 새 worker 요청을 만들지 않는다.
- 도움말의 칸 이름·고칠 칸 단추는 실제 입력 요소로 포커스를 옮기고 워크스페이스 포커스를 맞춘다. 값은 바꾸지 않는다.
- 안내를 닫아도 입력은 그대로다. 열림 상태는 탭 단위 `sessionStorage`의 화면 선택이며 저장 데이터가 아니다. 새 빈 프로젝트와 예제는 처음에 열려 있다.
- 기존 "샘플 값 채우기" 단추는 시험 의존 때문에 testid를 유지하되 "합성 샘플 값으로 바꾸기"로 글을 고쳐 입력을 바꾼다는 사실을 드러낸다.

## 하지 않는 것

실제 상품·사진·클라우드·구매 연결, 새 도메인 계약, 계정, 분석 전송, 승인된 화면 기준선(baseline) 교체, 측정 강제, 안내 진행 상태의 영구 저장.
