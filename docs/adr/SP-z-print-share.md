# SP-z-print-share — 도면·BOM·실행 가이드의 한 묶음 출력

상태: **채택**. 2026-10-07.

사용자 결정: JunTae Park (준태, 저장소 소유자), 2026-10-07 12:42 KST. 원문: "012·013·014·015·016 전부 채택한다. 게이트는 독립 리뷰 2회로 대체하고, user_merge도 네가 머지해라. 이후 z-노드도 같은 방식으로 끝까지 진행해."

이 기록은 z-print-share만 다룬다. 같은 발화의 이후 z-노드는 각 노드에서 구현한다. Fable NONE과 비작성자 A2는 독립 읽기 전용 검토 2회로 대체한다. 머지 권한은 감독자에게 위임된다. 기록은 [Dz-print-share](../../design/DECISIONS.md)이다. 이 채택은 런타임 배포, 계정, 결제, 클라우드, 사진 동의, 안전 인증, 출시, 실기기·실프린터 검증이 아니다.

## 문제

가족이나 설치 담당자가 같은 계획의 근거를 종이나 파일로 받아 실행해야 한다. 도면이 한 계획에서, 구매 목록이 다른 계획에서 나오면 사 온 물건과 놓을 자리가 어긋난다. 출력에서 미확인 검사나 자리를 정하지 못한 물건이 빠지면 읽는 사람은 "문제 없음"으로 오해한다. 반대로 출력은 앱 밖으로 나가므로, 사용자가 쓴 프로젝트 이름·물건 이름·구매 링크·진행 기록을 사용자 모르게 담으면 안 된다. CSV는 스프레드시트가 수식이나 하이퍼링크로 실행할 수 있고, 다시 가져오기 입력이 될 수 있어서는 안 된다.

## 결정

출력은 새 도메인 계약이 아니라 **하나의 PlanSnapshot과 그 계획에 대해 Rust가 낸 공간 투영(`projectSpatialView`)을 읽는 host 쪽 보기**다. Rust 소스, 프로토콜, capability, 스키마, 저장소는 바꾸지 않는다. 수량·가격·적합성·좌표는 Rust 값을 글자로 옮길 뿐 이 노드가 계산하지 않는다.

- 패키지(`features/print/package.ts`)는 순수 함수 `buildPrintPackage(input)`가 만든다. 시계·난수·로케일 의존 글자가 없어서 같은 스냅샷·투영·카탈로그·범위는 같은 패키지(JSON)이고, 그 SHA-256이 "출력 지문"이다. 구성은 표지(상태·물리 검토·구매 조건·카탈로그 출처·공간 치수), 위/앞 도면(번호 도면과 좌표 표, 그리지 못한 것 목록), 배치·물건별 위치·미배치, 모든 검사, 구매 목록과 비용과 구매 안내, 실행 순서다.
- 모든 쪽에 계획 ID(64자 전체)·단위 `mm`·입력 digest·카탈로그 버전과 출처·규칙 버전·포함 범위·"미확인은 통과가 아니다"가 붙는다. 인쇄 CSS의 `thead`/`tfoot` 반복 띠로 쪽 나눔과 무관하게 모든 쪽에 붙고, 도면은 새 쪽에서 시작한다. 데모 카탈로그는 "합성 데이터 — 실제 상품이 아닙니다"를 그대로 적는다.
- **revision 차단.** 도면 투영의 `source`가 `plan`이고 `planSnapshotId`·`inputDigest`·`catalogDigest`가 스냅샷과 같을 때만 만든다. 투영이 없거나(`drawing_loading`), 실패했거나(`drawing_unavailable`), 다른 계획에서 나왔거나(`revision_mismatch`·`input_mismatch`·`catalog_mismatch`) 형식 버전을 모르면(`projection_version`) 패키지도 CSV도 만들지 않고 이유를 글자로 보인다. 세션이 이미 거절한 투영(`projection_source_mismatch`)도 같은 차단이다.
- **생략 금지.** 조립 뒤 `verifyPackage`가 섹션마다 같은 revision인지, 배치·물건별 위치·미배치·검사·구매 줄·실행 단계·도면 요소 수가 Rust 스냅샷·투영과 같은지 센다. 하나라도 모자라면 `omitted_rows`/`section_revision`으로 출력하지 않는다. 미확인 수량은 `수량 미확인`, 미확인 금액·재고·배송은 `미확인`이다. 0·통과·기본값으로 바꾸지 않는다. 도면에 그리지 못한 요소는 이유와 함께 목록에 남는다. 진행 기록을 읽지 못하면 "읽지 못함"이고 전부 미완료로 적지 않는다. 빈 구역은 `없음` 행이다.
- **개인정보 포함 범위.** 출력마다 네 가지를 고른다: 프로젝트 이름, 내 물건·보유 수납함 이름, 구매 링크, 실행 진행 기록. 선택은 패널 안에만 있고 저장하지 않으며 기본은 모두 제외다(`공유용`, `모두 포함` 단추가 있다). 이름을 제외하면 물건·보유 수납함은 저장된 입력의 순서 번호("물건 1")가 되고, 알 수 없는 id는 글자로 찍지 않는다(사용자가 쓴 글일 수 있다). 카탈로그 상품 이름은 개인 글이 아니므로 남는다. 사진·첨부, 실제 위치 기록, 사용 피드백, 메모·근거 문서의 자유 서술, 계정·기기 정보는 범위와 무관하게 항상 제외한다. 선택된 범위는 모든 쪽 아래 띠와 CSV에 글자로 적힌다.
- **링크.** 구매 주소는 범위에서 켰을 때만, `http(s)` 한 줄 글자일 때만 평문으로 적는다(앵커·`href` 없음). 다른 형식은 "주소 형식 확인 불가"다.
- **CSV.** 두 종류(구매 목록, 계획 전체)이고 모든 줄이 계획 ID로 시작한다. 모든 칸은 기존 `csvCell`(따옴표, 선행 공백·제어문자 정규화 뒤 `= + - @` 앞에 `'`)을 지난다. 헤더는 카탈로그·출처 CSV 가져오기 열이 아니어서 `csvToEntries`/`csvToBatch`가 거절하고, 이 앱은 그 파일을 읽지 않는다. UTF-8 BOM을 붙인다. 기존 BOM 단독 CSV 단추는 이 패널의 "구매 목록 CSV"로 대체된다(링크는 범위 선택을 따른다).
- 화면은 계획 상세의 한 패널이다. 인쇄 미리보기는 `role="dialog"` `aria-modal` 전체 화면이고 열려 있는 동안 앱 루트는 `inert`, 포커스 가둠, Esc로 닫으면 연 단추로 복귀한다. 인쇄 단추는 `window.print()` 한 번이고, 인쇄 CSS는 미리보기가 열린 동안에만 앱을 숨긴다. 새 색 쌍·토큰은 없다. 미확인은 밑줄·굵게, 수납함과 안의 물건은 실선과 점선으로 색 없이 구분한다.
- 재현 fixture는 `apps/web/tests/fixtures/print-share/`이다. 공유 도메인 fixture 두 건(`candidate-contained-conditional`, `candidate-bounded-confirmed`)을 실제 WASM에 통과시켜 얻은 스냅샷·투영으로 범위 `share`/`full`마다 정적 HTML·계획 CSV·구매 CSV와 지문을 저장하고 바이트로 대조한다. `fixtures/`와 124건 manifest는 건드리지 않는다.

`BUILD_ID`는 `zari-domain-7`, `ruleVersion` `zari-domain-v2`, schema 1, canonical 1, protocol 1, exportVersion 1, 문서 `dbVersion` 2, live `DB_VERSION` 6은 그대로다. 새 명령·capability·DTO·저장소·마이그레이션은 없다.

## 하지 않는 것

PDF·이미지·서버 렌더링, 이메일·공유 링크·클라우드 전송, 사진 동의, 구매·결제 연결, 인쇄물 서명·인증, 도면의 새 계산이나 치수 선, 3D 출력, 다음 z-노드. 인쇄 쪽 나눔은 브라우저의 몫이며 실제 프린터 출력은 검증하지 않는다. 승인된 화면 baseline을 바꾸지 않고 기존 fixture 기대 바이트를 바꾸지 않는다.
