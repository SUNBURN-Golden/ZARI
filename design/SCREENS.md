# ZARI 핵심 화면 명세 — v0.1 / 초안과 구현 화면

이 문서는 화면 그림이나 구현 완료 보고가 아니라 재현 가능한 UI를 만들기 위한 계약이다. S01–S03은 처음 구현의 초안 계약이다. S04–S08은 로컬 앱에 있는 화면의 초안 항목이며 승인된 baseline이 아니다. 문자열과 수치는 설명용이며 실제 계산 결과를 뜻하지 않는다.

## 공통 여정과 정보 구조

시작·프로젝트 선택 → 공간 측정 → 물건·기존 수납함 → 정리 전략 → 방식·취향 → 배치안 비교·편집 → 구매목록·실행.

아래 세 화면을 우선 구현하되, 중간 단계의 입력과 선택을 생략한 가짜 자동 추천으로 연결하지 않는다. 전략은 사용빈도·활동·최소 구매처럼 물건 관리 기준이며, ‘화이트’는 시각적 취향이다. 사용자가 고른 전략을 몰래 바꾸지 않는다. 대안이 하나이면 하나, 없으면 이유를 표시한다.

첫 시작은 ‘공간 정리 시작하기’와 ‘샘플로 둘러보기’. 거대한 마케팅 hero나 로그인 강요를 넣지 않는다. 샘플 데이터는 demo임을 명시한다.

## S01 — 공간 측정

**목적:** 사용자가 실제로 사용할 내부 공간과 아직 모르는 치수를 구분해서 입력한다.

기본 구성은 프로젝트명·현재 단계, 폭/깊이/높이 입력, 연결된 공간 도형, 측정 도움말, 다음 행동이다. 처음에는 내부 폭·깊이·높이를 중심으로 보여주고, 전면 입구·장애물·오차는 명시적인 상세 단계로 이어진다. 상세 단계를 접어도 미확인 항목 수는 보인다.

입력 계약:
- 항상 보이는 레이블, 입력과 별도의 단위 선택, 최소 1rem 글자.
- 입력 중 문자열을 보존하고 blur·확인 시 Rust 정규화 결과를 사용한다. 붙여넣기와 십진수 cm를 검사한다. 한국어 IME 조합 중 입력을 강제로 변경하지 않는다.
- 빈 값은 unknown, 위치 0은 유효, 크기 0은 도메인 검증 대상이다. 소수점을 없애거나 단위를 임의 해석하지 않는다.
- 폭에 초점이 가면 가로 치수선, 깊이는 평면 방향, 높이는 정면 방향을 강조한다. 색과 텍스트 설명을 함께 사용한다.
- 숫자 입력 순서와 키보드 초점 순서는 일치한다. 장식 SVG는 보조적인 정보이며 텍스트 입력을 대체하지 않는다.

필수 상태:
| 상태 | 표시와 동작 |
| --- | --- |
| 처음/비어 있음 | 측정 위치와 필수값 안내. 샘플 시작과 혼동하지 않음 |
| 입력 중 | 아직 확정되지 않은 값 보존. 수정 때마다 공격적인 오류 알림 금지 |
| 유효하지 않음 | 해당 필드 바로 아래 이유, 제출 시 오류 요약과 첫 오류 이동 |
| 기본 치수만 있음 | 진행은 개략 계획 모드로 허용 가능하나 미확인을 유지 |
| 계산 중 | 현재 revision과 취소. 이전 결과는 최신처럼 보이지 않음 |
| 저장 실패 | 입력 유지, 다시 저장/내보내기 경로. 저장 완료 표기 금지 |

wide에서는 도형과 입력을 나란히, compact에서는 도형과 입력을 같은 순서로 쌓는다. 모바일 키보드가 켜져도 현재 필드와 오류가 가려지지 않는다.

완료 조건: mm/cm 왕복, 필드 오류 연결, 오차 미상 보존, 이전 단계 복귀 시 값 보존, keyboard-only 진행을 실제 실행한다.

## S02 — 배치안 비교와 편집

**목적:** 같은 공간에서 서로 다른 정리안을 이해하고, 실제 규격을 유지한 채 수정한다.

wide 구성: 상단 프로젝트·저장 상태·실행 취소/다시 실행, 좌측 공간/물건/전략, 중앙 정면도/평면도, 우측 선택 대상 inspector. 항상 모든 패널을 최대 폭으로 펼치지 않는다. compact는 도면과 명시적 탭·하단 상세 패널 중심이다.

도면 계약:
- Rust가 반환한 실제 placement와 공간 좌표를 사용한다. CSS 스타일 때문에 물리적 크기·gap을 변경하지 않는다.
- 도면 표시 스케일과 모델 단위를 분리한다. 줌·팬은 상태 변경이 아니라 뷰 변경이다.
- 클릭/탭 선택과 정밀한 숫자 위치 변경을 기본 제공한다. 드래그의 대안으로 ‘전면으로 이동’, 좌표 입력 등 단일 포인터 동작을 제공한다.
- 제품 이동/허용 회전만 가능하다. 실제 상품 도형을 resize해서 억지로 맞추지 않는다.
- 임시 드래그 위치는 ghost와 ‘검사 전’ 표시. 최종 배치는 Rust 검증을 거쳐 저장한다.
- 공간의 좌표축·방향·입구, 장애물, 선택 대상, 필요한 치수선이 구분되어야 한다.
- 도면을 사용할 수 없는 환경을 위한 배치 목록과 위치·규격·검사 텍스트를 제공한다.

inspector에는 제품 옵션, 외경/내경/출처, 담긴 물건, 검사별 상태와 이유, 교체 후보, 미확인 항목이 나타난다. 선택된 제품이 없어지면 초점을 유효한 목록 또는 도면 컨트롤로 복귀한다.

배치안 비교는 동일 공간·동일 축척을 기준으로 한다. 실제 후보의 신규 구매비·재사용 수량·미배정 물건·미확인 검사를 비교한다. 표면적인 문구만 바꾼 세 개 카드를 생성하지 않는다. 예산 미상은 0원이 아니다. z-strategy-library는 같은 계획 화면의 전략 라디오 아래에 비교를 둔다. 문장만 같은 결과는 하나고, 저장 전 선택은 핀이 아니며, 레시피가 받지 못하는 물건은 수량과 함께 남는다. z-pareto-comparison은 같은 계획 화면의 후보 옆에 구매비·재사용·선행 이동·미배정·미확인을 둔다. 차이는 Rust가 계산하고, 미확인은 0이 아니며, 다 쓴 탐색 예산은 전역 최적해가 아니다. z-incremental-replan은 그 비교 다음에 유지할 배치·물건·전략을 고르게 한다. 고정 좌표는 옮기지 않고, 막히면 풀 수 있는 고정을 보여 주며, 바꾸기는 명시 버튼이다. z-search-diagnostics는 탐색 상태 다음에 제품 없음·범위 밖 기하·확정 불가능·예산 소진을 둔다. 미상 측정은 제품 없음이 아니고, 더 큰 예산은 불가능의 증명이 아니며, 재현 자료는 로그 없이 내보낸다.

필수 상태:
| 상태 | 표시와 동작 |
| --- | --- |
| 배치 전 | 필요한 입력과 다음 행동 |
| 탐색 중 | 취소 가능, 확정 계획과 검색 중 미리보기 구분 |
| 외경 통과·내경 미상 | 외경 검사 범위만 pass, 내경은 unknown |
| 충돌/경계 초과 | 해당 대상·검사·위치 강조. 실제 차이값이 있으면 표시 |
| 입력 변경 | 과거 snapshot에 재계산 필요 표시, 오래된 응답 무시 |
| 해를 찾지 못함 | 상품 없음/정보 부족/예산/지원 범위/탐색 한도 구분 |
| 취소/Worker 실패 | 마지막 확정안·입력 보존, 재시도 가능 |
| 미배정 물건 | 결과에서 사라지지 않고 별도 목록에 유지 |

키보드 조작은 텍스트 편집과 충돌하지 않아야 한다. 도면 선택 상태에서만 이동 단축키를 적용하며, 1mm/10mm 등의 step은 UI에 명시하고 Rust로 검증한다. reduced motion에서는 보간 없이 상태 변화를 명확히 보여준다.

완료 조건: 동일 snapshot의 도면·BOM, 잘못된 드래그 거절, 입력 수정과 취소 경합, 키보드·단일 포인터 대안, 사용자 승인 전 baseline 미승격.

## S03 — 구매목록과 정리 실행

**목적:** 무엇을 몇 개 확보해야 하는지와 정리 순서를 구분해 실행한다.

상단은 계획 이름·revision·카탈로그 관측 시각·미확인 요약. 목록은 ‘이미 가진 것’, ‘새로 살 것’, ‘아직 확인할 것’으로 나눈다. 상품 소계·배송비 확인 상태·미확인 가격을 구분한다.

각 행에는 정확한 옵션명, 필요 개수, 보유 사용 개수, 구매 단위와 묶음 수, 확보 개수와 잉여, 가격 확인 시각, 판매처 링크 상태가 있다. 예: 필요 5개 / 2개 묶음 → 3묶음 주문 / 6개 확보 / 1개 남음은 합성 예시다. 화면 계산은 Rust BOM을 사용한다. z-offer-bundles는 같은 화면에 판매처 비교를 둔다. 필요 3개 / 2개 묶음은 2묶음과 잔여 1개다. 배송비가 미확인이면 무료나 0원으로 합계에 넣지 않는다. 품절 교체는 그 계획의 새 revision 하나에서 도면·목록·순서를 같이 바꾼다.

버튼은 ‘판매처에서 보기’, ‘목록 내보내기’, ‘정리 순서 보기’처럼 실제 기능과 일치시킨다. 장바구니·결제를 연동하지 않았는데 ‘전체 구매 완료’ 같은 UI를 넣지 않는다. URL 미확인·재고 미상은 명시한다. 외부 링크는 적절한 accessible name과 새 창 안내를 제공한다.

실행 가이드는 같은 PlanSnapshot의 ActionStep과 선행 조건을 그대로 따른다. 수납함을 사용하는 v1 계획은 필요한 제품의 도착 확인 → 공간 비우기·물건 분류·외부 staging 준비 → staging에서 내용물 담기 → 검증된 설치 순서로 내용물이 담긴 수납함 삽입 → 라벨·미배정 확인으로 구성한다. 보유 수납함에도 같은 적재·삽입 원칙을 적용하며, 구획 안에서 내용물을 담는 미지원 동작을 안내하지 않는다. 직접 배치한 물건은 검증된 직접 삽입 단계를 사용하고, 구매 없는 계획에는 구매·도착 단계를 만들지 않는다. UI가 이 순서를 별도로 재계산하지 않는다. 체크 상태는 안정적인 ActionStep ID로 관리한다. 새 계획에서 물건·배치가 달라졌으면 이전 완료 체크를 자동 상속하지 않는다.

필수 상태:
| 상태 | 표시와 동작 |
| --- | --- |
| 추가 구매 없음 | 0원 자체를 경고하지 않고 재사용·정리 순서 제공 |
| 일부 가격 미상 | 확인된 소계와 미확인을 분리. 총액 확정 금지 |
| 배송비 미상 | 별도 안내. 무료로 계산 금지 |
| 입고/도착 전 | 구매·도착·설치 완료를 구분 |
| 계획 수정 | 목록이 과거 계획이면 재계산 또는 이전 버전 표시 |
| 실행 중/저장 실패 | 체크 상태 보존·재시도 안내 |

wide는 목록과 요약, compact는 의미 있는 행별 계층으로 재배치한다. 중요한 옵션·치수·미확인 경고를 말줄임만으로 숨기지 않는다. 인쇄/내보내기에도 demo·버전·미확인 상태를 유지한다.

완료 조건: 도면 수량과 판매 묶음의 구분, 보유품 중복 차감 방지, 가격 미상, 새 revision의 체크 이월 정책, 저장 복구를 검증한다.

## S04 — 다음에 확인할 사실 (초안)

**목적:** 비어 있거나 서로 다른 기록을 Rust가 고른 순서대로 연다. 목록은 계산 결과가 아니다.

앱의 `next-facts`가 이 표면이다. 행은 목록(`ul`/`li`)이고, 한 행을 열면 상세 칸이나 카탈로그로 간다. 입력이 바뀌면 이전 목록을 최신처럼 두지 않는다. 승인된 화면은 아니다.

## S05 — 상세 사실 (초안)

**목적:** 값, 오차, 출처를 한 칸에서 고친다. 빈 수량은 0이 아니다.

앱의 상세 패널이 이 표면이다. 그룹을 고르고 칸을 고른 뒤 원문을 유지한다. Rust가 정규화한다. 승인된 화면은 아니다.

## S06 — 단계 자격 가이드 (초안)

**목적:** 채택한 PlanSnapshot의 실행 순서를 보여주고, 완료할 수 있는 단계와 막힌 단계를 구분한다.

앱의 `#accepted-guide`가 이 표면이다. 기다리거나 조건이 막힌 확인란은 이유를 글자로 붙인다. 읽기 전용이면 완료를 확인란 없이 글로 보여 준다. 자격 판정은 Rust다. 승인된 화면은 아니다.

## S07 — 복구 패널 (초안)

**목적:** 저장 실패, 충돌, 손상, 닫기 거절, 워커 실패에서 입력과 다음 행동을 유지한다.

앱의 `recovery-panel`이 이 표면이다. 실패를 성공으로 바꾸지 않는다. 승인된 화면은 아니다.

## S08 — 중단된 계산 (초안)

**목적:** 계산이 중단되었을 때 이전 계획과 입력이 그대로임을 알린다.

앱의 `search-status`가 이 표면이다. `role="status"`로 중단·완료·실패를 읽는다. 중단을 완료로 적지 않는다. 승인된 화면은 아니다.
